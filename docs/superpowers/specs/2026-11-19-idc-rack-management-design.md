## 1. 引言

### 1.1 背景与目标

IDC 机房的日常运维依赖对机柜、U 位与设备的准确台账。当前需求聚焦机柜域，解决两类问题：

1. **资产台账**：准确登记机房、机柜、设备及其 U 位与位置编码，支持盘点。
2. **容量决策**：实时掌握机柜的剩余 U 位、剩余功率、剩余承重与负载率，支撑设备上架与扩容决策。

系统以机柜为核心对象，设备上架/下架/移位时自动重算容量，避免账实不符。

### 1.2 范围

- **本期范围（In Scope）**：机房管理、机柜管理、设备管理、精确 U 位放置与可视化、上下架/移位、容量校验与预警、查询报表、操作审计、扩展点预留。
- **不在本期范围（Out of Scope）**：IP 地址实际管理、动环/监控实时采集、工单审批流、资产采购/报废流程 —— 本期仅预留接口与字段，不实现功能。
- **规模假设**：单机房/小规模，几十至几百个机柜，内部使用。

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| U | 机柜高度单位，1U = 44.45mm；机柜常见总高 42U / 47U |
| 机柜面 | 机柜前面板(A面) / 后面板(B面)，两面 U 位独立计算 |
| 起始 U | 设备占用 U 位区间的起始编号（自下而上计数，可在实现时配置方向） |
| 占用 U 数 | 设备纵向占用的 U 位格数 |
| 额定功率 | 机柜设计允许的最大供电功率（kW） |
| 承重上限 | 机柜设计允许的最大设备总重量（kg） |
| 负载率 | 已用功率 / 额定功率，用于告警 |
| 位置编码 | 机柜在机房中的唯一业务编码（如 `A-03-12`） |
| 放置 (Placement) | 设备与机柜某面某段 U 位的关联记录，是容量计算的依据 |

## 2. 总体描述

### 2.1 用户角色

| 角色 | 职责 |
|---|---|
| 管理员 | 全部配置与数据维护、用户与权限管理 |
| 运维人员 | 机柜/设备台账维护、设备上下架与移位、查看容量与可视化 |
| 只读用户 | 查询检索、查看报表与可视化，不可修改数据 |

### 2.2 典型场景

1. 新增机柜：录入名称、位置编码、存放位置、总 U 数、额定功率、承重上限。
2. 设备上架：选择机柜与面，指定起始 U 与占用 U 数，系统校验 U 位冲突、总 U 数、功率、承重后落库，并重算容量。
3. 查看机柜：以正/背面 U 位图查看占用、空闲、预留状态，查看剩余 U/功率/承重与负载率。
4. 设备移位/下架：释放原 U 位，自动重算源机柜与目标机柜容量。
5. 审计追溯：按操作人/时间/对象检索变更记录。

### 2.3 设计约束

- 容量数据**由放置记录实时计算，不冗余存储**，避免账实不符。
- 一期负载数据**人工录入**，架构预留采集切换能力。
- 技术方向：Python 生态，轻量自研（路线 A），不引入 NetBox 等重型平台作为底座。

## 5. 容量计算与校验规则

### 5.1 计算规则

统计口径：每台机柜按 A/B 两面合并统计功率/承重；U 位按面独立计算。

- `已用U(每面) = Σ 在架设备的占用U数`，且每面 `已用U ≤ 总U数`
- `剩余U(每面) = 总U数 − 已用U`
- `已用功率（台账累计） = Σ 在架设备功耗(W)`；`剩余功率 = 额定功率 − 已用功率`
- `已用承重 = Σ 在架设备重量(kg)`；`剩余承重 = 承重上限 − 已用承重`
- `当前负载 = current_load_kw`（一期由运维人工录入的实测 PDU 负载，非设备功耗累加）
- `负载率 = 当前负载 / 额定功率`；若未录入当前负载，则回退为 `已用功率（台账累计） / 额定功率` 作为预估值并标注"估算"

> 口径区分：功率/承重的**强校验**（§5.2 规则 3/4）始终基于"台账累计值"（设备功耗/重量之和），用于防止账面上架超载；"当前负载"仅用于负载率展示与告警（规则 5），不参与强校验。两者来源不同，不可混用。

### 5.2 校验规则

> FK = 强阻断（不允许提交），W = 告警（允许提交但提示）

| # | 规则 | 处理 |
|---|---|---|
| 1 | 同一面同一 U 被重复占用（U 位冲突） | FK 阻断 |
| 2 | 起始 U + 占用 U − 1 > 总 U 数 | FK 阻断 |
| 3 | 已用功率 + 新设备功耗 > 额定功率 | FK 阻断（可配置软/硬阈值） |
| 4 | 已用承重 + 新设备重量 > 承重上限 | FK 阻断（可配置软/硬阈值） |
| 5 | 负载率 > 告警阈值（如 80%） | W 告警，不阻断 |
| 6 | 设备下架/移位 | 自动释放原 U 位并重算 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 易用性 | 常见操作（上架/查余量）≤ 3 次点击 |
| 一致性 | 容量数据由放置记录实时计算，不冗余存储 |
| 可靠性 | 关键变更写入审计日志；删除含设备的机柜需二次确认 |
| 性能 | 数百机柜、数千设备规模下页面响应 < 1s |
| 可维护性 | 模块按领域拆分：room / rack / device / placement / audit |

## 7. 架构建议（路线 A：轻量自研 / Python 生态）

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Vite + TypeScript，Element Plus | 机柜 U 位图用 CSS Grid 自绘即可，无需重型图形库 |
| 后端 | Django 5 + Django REST Framework | Python 生态契合，ORM + Admin 快速出台账后台 |
| 数据库 | PostgreSQL 16 | 直接使用 PostgreSQL，开发环境也用 compose 内 PostgreSQL，避免开发/生产差异；数据存于具名卷持久化 |
| 部署 | Docker Compose（db + web + frontend，dev/prod 分层覆盖） | 开发、测试、部署统一用 compose，环境一致、运维成本低 |
| 权限 | Django auth + 简单角色（管理员/运维/只读） | 满足审计所需的操作人身份 |

**U 位可视化实现**：每个机柜视图按 A/B 两面、从上到下渲染 `总U数` 个格子；设备按其起始 U/占用 U 跨格显示，颜色区分状态；点击格子可发起上架/下架操作。

### 7.1 扩展点设计（本期仅定义接口，不实现）

- **IPAM**：`Device` 预留 `ip_addresses` 关联，未来接 IP 地址表。
- **资产生命周期**：`Device` 预留 `purchase_date`、`warranty_end`、`status`（在用/维保/报废）字段。
- **动环采集**：`Rack` 预留 `metrics_endpoint` 配置；负载数据可从"人工录入"平滑切换为"采集写入"。

## 8. 验收标准

| 编号 | 验收项 |
|---|---|
| AC1 | 能新建机房/机柜/设备，机柜正确保存总 U 数、额定功率、承重上限、位置编码 |
| AC2 | 能在一台机柜的指定面、指定起始 U 上架一台设备，U 位图正确显示占用 |
| AC3 | 剩余 U / 剩余功率 / 剩余承重随上下架实时重算，与台账一致 |
| AC4 | U 位冲突、超总 U、超功率、超承重四类操作被阻断并给出明确提示 |
| AC5 | 负载率超阈值产生告警但可继续上架 |
| AC6 | 设备下架/移位后原 U 位释放，容量回升 |
| AC7 | 每次关键变更都能在审计日志中查到操作人/时间/前后值 |

## 9. 参考资料

> 以下为设计参考的来源与选型判断，非强制依赖。

- **NetBox**（`netbox-community/netbox`，Apache 2.0）：网络自动化"事实源"，DCIM 域含 Site / Rack / Device / Module 及 U 位、电源、线缆模型 —— 本项目领域模型的主要参照。
- **openDCIM**（`opendcim/opendcim`，GPLv3）：Vanderbilt 出品的经典 DCIM，机柜视图与容量管理完整。**注意**：原作者已宣布寻找接手者并计划停止维护（最终版 26.01），仅作功能参考，不选作底座。
- **RackTables**（`racktables/racktables`，GPL）：老牌机柜 / IP / VLAN 管理，位置与机柜对象模型可参考。
- 说明：用户提供的微信参考文章因验证码（"环境异常，完成验证后即可继续访问"）未能读取；GitHub star 精确数因搜索工具额度不足未逐一核实，以上为业界公认的高星项目。

### 9.1 路线对比（选型记录）

| 路线 | 描述 | 取舍 |
|---|---|---|
| A 轻量自研（**选用**） | Django + Vue 自建，模型参考 NetBox 精简到机柜域 | Python 生态契合，U 位可视化/容量校验自主可控，无冗余功能 |
| B NetBox 二次开发 | 基于 NetBox 定制 | 模型成熟、star 高，但功能远多于需求，定制与升级维护成本高 |
| C openDCIM/RackTables 改造 | 经典 DCIM 改造 | 自带机柜视图，但均为 PHP/MySQL 且 openDCIM 停止维护，与 Python 倾向不符 |
